# ポスター管理アプリ 要件定義書

作成日: 2026-08-18
対象: 品川区内の政治家ポスター掲示場所の管理

---

## 1. 目的と背景

政治家のポスター掲示場所（所有者・連絡先・掲示条件）を一元管理し、
**台帳・地図・戦略立案**の3つの視点から扱えるようにする。

現在は Excel / スプレッドシートで管理しているが、以下の課題がある。

- 地図上での位置把握ができない（住所の羅列だけでは戦略が立たない）
- 複数端末での閲覧・更新ができない
- 現地で確認・更新する手段がない

---

## 2. 利用者と利用シーン

| シーン | 場所 | 端末 | 主な操作 |
|---|---|---|---|
| 台帳管理（メイン） | 事務所 | PC | 入力・編集・CSV入出力・列の追加 |
| 現地確認・更新 | 屋外 | スマホ | 現在地周辺の確認、貼替日のワンタップ更新、ピン位置の補正 |
| 戦略立案 | 事務所 | PC | 地図の俯瞰、色分けによる分析、空白地帯の把握 |

**利用者**: 個人別台帳型。ログインした Google アカウントごとに独立したデータを持ち、
他人のデータは一切見えない。複数の候補者のポスターを管理できる。

**ログインしなくても全機能が使える**（データはその端末の中だけに保存される）。
複数の端末で同じ台帳を見たいときにログインする。詳細は 3.4。

---

## 3. システム構成

### 3.1 決定事項と根拠

| 項目 | 決定 | 根拠 |
|---|---|---|
| 配信 | **Firebase Hosting** | GitHub Pages では iPhone / iPad で Google ログインが通らない（後述） |
| コード管理 | GitHub（非公開リポジトリ） | 個人情報を扱うため。GitHub Actions から Firebase へ自動デプロイ |
| 認証 | Firebase Authentication（Google） | 既存プロジェクトで実績あり。**ログインは同期のためで、使用の条件ではない**（3.4） |
| データベース | Cloud Firestore | 複数端末の同期、オフライン対応が標準機能 |
| 未ログイン時の保存先 | **IndexedDB（端末内）** | アカウントも通信も無しに使えるようにするため（3.4） |
| 地図 | Leaflet + OpenStreetMap タイル | 無料・APIキー不要 |
| ジオコーディング | 国土地理院API（第一候補） | 日本の住所に強く、無料。Nominatim は一括利用が規約で禁止 |
| 写真 | **対象外**（初版では実装しない） | 構成を単純に保つ。後から追加可能 |

### 3.2 なぜ GitHub Pages を使わないか

Firebase の Google ログインは、認証ハンドラーが Google へ遷移する**前**に
sessionStorage へ状態を書き、戻った**後**に読む。
iOS の WebKit はストレージをドメイン単位で分割するため、
配信元（`taku3516.github.io`）と authDomain（`*.firebaseapp.com`）が異なると
書き込み先と読み出し先が別領域になり、ログインが失敗する。

- これは Safari だけでなく iOS 版 Chrome でも起きる（中身が WebKit のため）
- パソコン（Blink系）では発生しないため「PCで動いた」は検証にならない
- `signInWithRedirect` に変えても、**ドメインが一致していなければ解消しない**

→ 配信元を Firebase Hosting に揃えることが唯一の解決策。

**副次的な利点**: GitHub Pages は非公開リポジトリからの配信に有料プランが必要だが、
Firebase Hosting なら無料で非公開リポジトリを維持できる。

### 3.3 ログイン方式の出し分け

| 環境 | 方式 |
|---|---|
| パソコン | `signInWithPopup` |
| iOS（iPhone / iPad） | `signInWithRedirect` |
| 判定不能 | `signInWithPopup`（動く環境を壊さない） |

---

### 3.4 ログインしないで使える（2026-08-19 変更）

**ログインは「複数の端末で同じ台帳を見る」ためのもので、使用の条件ではない。**

当初はログインを通らなければ何も操作できなかった。これを次のように改めた。

| 状態 | 保存先 | 見え方 |
|---|---|---|
| ログインしていない | **この端末の中（IndexedDB）** | 全機能が使える。他の端末には表示されない |
| ログインしている | Firestore（アカウント配下） | 同じアカウントの端末すべてで自動的に同期される |

**一度もログインしたことがない端末では、Firebase SDK を読み込まない。**
`localStorage` に「ログインを試みたことがある」印を持ち、その印がある場合だけ
`auth.js` / `db.js` を動的に読み込む。圏外でもアカウントが無くても起動できる。

印は**成功時ではなく試行時**に付ける。遷移方式のログインは Google の画面へ
飛んで戻る間にページが読み直されるため、成功時に付ける作りだと
戻ってきた時点で印が無く、ログインしたのに端末内保存のままになる。

保存層は `db.js`（Firestore）と `local-db.js`（端末内）が**同じ関数の並び**を持つ。
画面側は変数1つを差し替えるだけで、呼び出し方は変わらない。

**取り込み（端末内 → アカウント）**

ログインすると、端末内にデータがある場合だけ取り込みを尋ねる。黙って移さない。

- 取り込みは**常に新しい台帳を足す形**で行い、アカウント側の既存の台帳は変更しない
  （同じ番号のポスターが両方にあったとき、どちらが正しいかは機械には決められない。
  混ぜたい場合は CSV 取り込みが使える）
- 名前がぶつかる場合は印を付けて区別する
- **取り込んだ後も端末内のデータは残す。** 取り消せない操作を利用者の指示なしに行わない。
  確認できたら設定画面から消せる

## 4. データ構造

### 4.1 全体像

```
users/{uid}
  └── candidates/{candidateId}        … 候補者（＝台帳）。複数作成・削除できる
        ├── (メタ) name, columns[], colorRules[]
        └── posters/{posterId}        … ポスター掲示場所
```

1人のログインユーザーが**複数の候補者台帳**を持ち、画面上部で切り替えて使う。
候補者の追加・削除は自由に行える。

### 4.2 ポスター掲示場所（固定項目）

| 分類 | キー | 表示名 | 型 |
|---|---|---|---|
| 識別 | `no` | 番号 | 文字列 |
| 日付 | `postedOn` | 掲示日 | 日付 |
| 日付 | `lastReplacedOn` | 最新貼替日 | 日付 |
| 人 | `introducer` | 紹介者 | 文字列 |
| 人 | `owner` | 所有者 | 文字列 |
| 連絡先 | `phone` | 電話番号 | 文字列 |
| 連絡先 | `mobile` | 携帯番号 | 文字列 |
| 連絡先 | `email` | メール | 文字列 |
| 連絡先 | `contactAddress` | 連絡先住所 | 文字列 |
| 場所 | `placeName` | 掲示場所 | 文字列 |
| 場所 | `postalCode` | 郵便番号 | 文字列 |
| 場所 | `address` | 掲示住所 | 文字列 |
| 区分 | `district` | 地区 | 選択式（品川区の町字 + 「区外」） |
| 区分 | `areaDetail` | 詳細エリア | 選択式（町丁目）。掲示住所から自動補完 |
| 地図 | `showOnMap` | マップ掲載 | チェック（地図に表示するか） |
| 地図 | `lat` / `lng` | 緯度 / 経度 | 数値 |
| 地図 | `coordFixed` | 座標確定 | チェック |
| 仕様 | `size3L` / `size3S` | 3連大 / 3連小 | 数値（枚数） |
| 仕様 | `size2L` / `size2S` | 2連大 / 2連小 | 数値（枚数） |
| 条件 | `needLadder` | 要脚立 | チェック |
| 条件 | `plaDan` | プラ段 | チェック |
| 条件 | `indoor` | 室内 | チェック |
| その他 | `note` | 備考 | 文字列 |
| 条件 | `otherParty` | 他党 | チェック |
| 管理 | `updatedAt` / `updatedBy` | 更新日時 / 更新者 | 自動 |

**追加提案した項目**

- `coordFixed`（座標確定）… 地図上で手動移動した座標を、ジオコーディング再実行で
  **上書きさせない**ための印。これが無いと現地で直した位置が勝手に戻る。
- `status`（状態: 掲示中 / 撤去済 / 交渉中）… 削除ではなく状態で持てば履歴が残る。

### 4.3 カスタム列（新規列の追加）

固定項目に加えて、利用者が**自由に列を追加**できる。

- 列定義は候補者ごとに `columns[]` として保持する
- 型: 文字列 / 数値 / 日付 / チェック / 選択式
- 各列は 表示名・並び順・表示/非表示 を設定できる
- 値は各ポスターの `custom` 配下に保存する（例: `custom.回覧板担当 = "田中"`）
- **CSV の入出力もカスタム列に対応する**

## 5. 機能要件

### 5.1 一覧（台帳）画面

- 表形式での表示・並べ替え・絞り込み・全文検索
- セルの直接編集、行の追加・複製・削除
- 列の表示/非表示の切り替え、並び替え
- **新規列の追加・編集・削除**
- 複数行の一括編集（例: 選択した行の貼替日をまとめて今日にする）

### 5.2 地図画面

- 住所からの自動ピン生成（ジオコーディング）
- **ピンのドラッグ移動**（移動すると `coordFixed` が自動で立つ）
- **ピンの削除**
- **地図クリックでの新規ピン追加**（逆ジオコーディングで住所を補完）
- ピンのクラスタリング（件数が増えても潰れないように）
- 現在地表示と、現在地周辺のポスター一覧
- ピンをタップ → 詳細表示 → 貼替日をその場で更新

### 5.3 ピンの色分け（重要）

**任意の軸で色を変えられる**ようにする。設定は保存し、複数のルールを切り替えられる。

| 色分けの軸 | モード | 用途 |
|---|---|---|
| ポスター種別（3連大など） | 枚数のしきい値 | どこに大きいポスターがあるか |
| 地区 / 詳細エリア | カテゴリ | 担当区分の把握 |
| 最新貼替日からの経過 | 期間のしきい値 | 貼替が必要な場所の把握 |
| 要脚立 / プラ段 / 室内 | 有無 | 作業計画（脚立を積むべき日） |
| 他党 | 有無 | 競合状況 |
| 状態 | カテゴリ | 交渉中の場所の把握 |
| 任意のカスタム列 | 型に応じて | 自由な分析 |

- 凡例は選択した軸から**自動生成**する
- 色はデジタル庁のパレットから選ぶ（後述）

### 5.4 ダッシュボード（戦略立案）

- 総掲示数 / 総枚数、種別ごとの内訳
- 地区別の枚数分布
- **貼替が古い順トップ20**（次に回るべき場所）
- 座標未確定（地図に出ていない）件数
- 要脚立の件数
- 他党が併存している場所の数
- 掲示密度のヒートマップ（**空白地帯の可視化**）

### 5.5 CSV 入出力

**用途**: 秘書側で最新データを更新し、エクスポートしたものを議員にインポートしてもらうことで、
議員が最新版を閲覧できるようにする。

- **エクスポート**
  - **いま一覧に出ている行**（絞り込み後）を出力する。
    「脚立が要る場所だけ渡す」といった使い方ができる
  - 列は現行Excelの24列 → 緯度/経度/座標確定/状態 → カスタム列 の順
  - 文字コードは **BOM付きUTF-8**
    > **Shift_JISでの書き出しは行わない。** ブラウザの `TextEncoder` はUTF-8のみに
    > 対応しており、Shift_JISへの変換には大きな変換表が必要になる。
    > BOM付きUTF-8なら Excel は文字化けせずに開くため、目的は達せられる
  - チェック項目は `○` と空欄で書き出す
- **インポート**
  - 文字コードは **BOM付きUTF-8 / BOMなしUTF-8 / Shift_JIS を自動判別**
    （読み取りは `TextDecoder` が対応しているため費用がかからない）
  - 列名で突合。突合キーは `番号`
  - **CSVに無い列は既存の値をそのまま残す**（一部の列だけのCSVで他が消えない）
  - チェック項目は書き方の揺れを吸収する（`○ ◯ ● 1 はい TRUE ✓ yes` を「あり」とみなす）
  - 差分マージ（CSVに無い行は残す）と全置換（CSVに無い行は削除）を選べる
  - **取り込み前に必ず確認画面を出す**（追加◯件／更新◯件／削除◯件、
    台帳に無い列、警告、取り込み後の例）。確定するまで一切書き込まない
  - 台帳に無い列は「新しい列として追加するか」を選べる
- **取り込みを止める条件**
  - 見出しに `番号` が無い（突合の鍵が無い）
  - **CSVの中で番号が重複している**（どちらが正か機械には決められないため、
    黙って片方を採らずに止める）
  - 番号が空の行は取り込まず、行番号を挙げて知らせる
- **警告にとどめる条件**
  - 掲示住所の重複（同じ建物に複数枚ということもあり得るため止めない）

> **運用上の注意**: この受け渡しは**一方向**である。
> 議員側で編集しても秘書側には反映されず、次のインポートで上書きされる。

### 5.6 候補者（台帳）の管理

- 候補者の新規作成・名称変更
- 画面上部での切り替え（最後に見ていた候補者を覚える）
- **保管（アーカイブ）** … 一覧から外すがデータは消さない。あとで戻せる

**完全削除については保留。** 現状は保管のみを提供する。

> Firestore は入れ子のコレクションを一緒に消さない。候補者だけを消すと
> ポスターが取り出せないまま残り続けるため、削除は「ポスターを全部消してから
> 候補者を消す」順序で行う必要がある。処理は `deleteCandidateForever` として
> 実装済みだが、取り消せない操作のため画面には出していない。

### 5.7 オフライン対応

- Firestore の永続化を有効化し、電波の悪い場所でも閲覧・編集できるようにする
- 復帰時に自動同期する

## 6. セキュリティ / 個人情報

### 6.1 何が本当の防御か

Firebase の Web API キーは**秘密情報ではない**。プロジェクトの識別子であり公開前提の設計。
実際にデータを守っているのは次の2つ。

1. **Firestore セキュリティルール** — `/users/{uid}/**` は `request.auth.uid == uid` のときのみ読み書き可
2. **承認済みドメイン** — Firebase Authentication に登録したドメインからのみ認証できる

個人別台帳型のため、**データ構造そのものがアクセス境界**になる。
他人のデータは技術的に取得できない。

### 6.2 遵守事項

- リポジトリは**非公開**にする
- `*.csv` および `data/` を `.gitignore` に登録し、実データがコミットされないよう機械的に止める
- 所有者の氏名・電話・メール・住所はコード内・ドキュメント内に一切書かない
- サンプルデータは架空の値のみを使う

## 7. UI / UX 方針

参考: デジタル庁「ダッシュボードガイドブック」
https://www.digital.go.jp/resources/dashboard-guidebook

### 7.1 採用する考え方

- **カラーパレットは7色に限定**
  Solid Gray（灰）/ Blue / Light Blue / Cyan / Green / Orange / Red
- **グリッドシステム**で配置を揃え、要素ごとに余白を変えない
- 色は**意味のあるところにだけ**使う。装飾に使わない
  （基調は灰色。データと状態表示にのみ色を割り当てる）
- グラフは棒・折れ線・円など、**目的に合った標準的なもの**を選ぶ

### 7.2 避けること（いわゆる「AI生成っぽさ」の原因）

- 紫〜青のグラデーション背景
- 過剰な角丸と影
- 意味のない色分け（項目ごとに違う色を振る）
- 絵文字によるアイコン代用
- 中央寄せの大きな見出しと余白過多のカード並び

### 7.3 アクセシビリティ

- コントラスト比は WCAG AA（本文 4.5:1、大きな文字 3:1）を満たす
- **色だけで情報を伝えない**（ピンは色 + 形 / ラベルでも区別できるようにする）
- キーボードのみで台帳の入力が完結すること

## 8. 確定した仕様の補足

### 8.1 地区 / 詳細エリア

`地区` と `詳細エリア` は**親子関係**にある。

| 項目 | 粒度 | 例（区内） | 例（区外） |
|---|---|---|---|
| `地区` | 町字 | 大井 / 西五反田 / 荏原 | 「区外」 |
| `詳細エリア` | 町丁目 | 大井一丁目 / 西五反田三丁目 | 市区町村名 |

**掲示住所から自動補完する。**

`掲示住所` には既に町丁目が含まれているため、ジオコーディングで正規化した住所から
`地区` と `詳細エリア` を機械的に切り出す。利用者はどちらも入力しなくてよい。

- 例: 「品川区大井一丁目2-3」→ `地区` = 大井、`詳細エリア` = 大井一丁目
- 品川区以外の住所 → `地区` = 区外、`詳細エリア` = 市区町村名
- 自動補完した値は**手動で上書きできる**（上書きしたものは再補完で戻さない）

> **町丁目の一覧をアプリに同梱しない理由**
> 手書きの一覧は誤りや改称の追随漏れが起きる。正規化済み住所からの切り出しなら
> 常に実データと一致し、表記揺れも構造的に発生しない。

### 8.2 マップ掲載 / 他党

- `マップ掲載` … 地図上に掲載されているか否か（チェック）
- `他党` … **他の政党や候補者のポスターも掲載されているか否か**（チェック）
  → 文字列ではなく有無。色分けの軸およびダッシュボードの集計対象とする

### 8.3 CSV の列対応

現行 Excel のヘッダーは第4.2節の固定項目と**過不足なく一致**する。
そのため列名の変換表は不要で、ヘッダー名をそのまま突合キーに使う。

```
番号, 掲示日, 最新貼替日, 紹介者, 所有者, 電話番号, 携帯番号, メール,
連絡先住所, 掲示場所, 郵便番号, 掲示住所, 地区, 詳細エリア, マップ掲載,
3連大, 3連小, 2連大, 2連小, 要脚立, プラ段, 室内, 備考, 他党
```

エクスポート時はこの24列を先頭に、その後ろへ 緯度 / 経度 / 座標確定 /
カスタム列 を並べる（既存の Excel でそのまま開けるようにするため）。

### 8.4 貼替の目安期間（保留のまま進める方法）

「何ヶ月で要対応とするか」は地区や掲示条件によって変わるため保留。
**専用の「要対応」項目は作らない。**代わりに第5.3節の色分けルールに
「最新貼替日からの経過期間」の軸を持たせ、**しきい値を利用者が自由に設定・保存**できるようにする。

- 「6ヶ月以上を赤」「1年以上を赤・半年以上を橙」など、後からいくらでも変えられる
- 地区ごとに基準が違う場合は、絞り込みと組み合わせて別ルールとして保存する
- ダッシュボードの「貼替が古い順トップ20」は**しきい値に依存しない**ため、保留のまま実装できる

→ **決められない値を、決めなくてよい形に落とし込む。**
